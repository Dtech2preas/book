# DTECH Student Marketplace - Full System Architecture & Documentation

## 1. Overview and Purpose
**What it is:**
The DTECH Student Marketplace (also known as DTECH Book Exchange) is a peer-to-peer textbook marketplace tailored for students. It serves as an organized, centralized platform where students can browse available textbooks to buy or list the textbooks they are looking for.

**Who runs it:**
The project is run by Seakwa Jonas Mochebane (online alias: PREASX24), a South African technology founder, as part of the broader DTECH ecosystem.

**What it's for:**
Instead of students relying on scattered group chats or social media to find or sell textbooks, this application provides a centralized and clean UI to bridge the gap. It connects buyers directly with sellers or requesters over WhatsApp, making it easy to facilitate textbook exchanges without handling financial transactions directly on the platform.

## 2. High-Level Architecture
The system is a fully serverless web application and native Android ecosystem that utilizes a separated Frontend and Backend architecture:

* **Frontend (Web):** A series of static HTML, CSS, and JS files (`index.html`, `admin.html`, `seller-manage.html`, `sell.html`, `request.html`, `ambassadors.html`) served directly to the user's browser. It uses plain Vanilla JavaScript to make HTTP requests to the backend API and handles client-side caching using IndexedDB for offline resilience. The UI theme follows a "DTech Blue & Black" branding, using a dark mode aesthetic with `#00D2FF` cyan accents. Frontend configuration is accessed asynchronously by awaiting `window.appConfigPromise` in `config.js` to prevent race conditions.
* **Backend (API):** A robust Cloudflare Worker (`worker.js`) script handles all routing, logic, authentication, text extraction (OCR), and push notifications.
* **Database:** Cloudflare KV (Key-Value) storage persists all data natively as JSON objects.
* **Image Hosting:** Images are converted to Base64 strings and stored directly within the KV store's JSON objects. To optimize initial load times, the `GET /` list endpoint dynamically strips out the base64 image data. Images are loaded lazily on demand via a dedicated `GET /image?id=...` endpoint that returns binary image data.
* **Android Native Wrappers:** Built using Gradle, providing native experiences and push notifications for admins, ambassadors, and general users.
* **CI/CD pipeline:** Managed via GitHub Actions to automate Cloudflare Worker deployments and Android APK builds.

## 3. The Backend API (`worker.js`)
The `worker.js` script handles cross-origin requests (CORS), ensuring `Authorization` is explicitly included in the `Access-Control-Allow-Headers` for both preflight and regular requests. It routes operations based on the HTTP method and URL path. Admin endpoints require the `X-Admin-Password` header, mapped globally in the frontend as `adminPass`.

### Key Endpoints and Logic:
* **`OPTIONS *`**: Handles CORS preflight requests.
* **`GET /`**: Fetches a list of all books from the KV store (`book:` prefix). Filters for `status: 'active'`, returning a lightweight array of book JSON objects (strips out `image` and `sellerCode` for speed and privacy).
* **`GET /?id=<book_id>`**: Fetches the full, unredacted JSON object for a specific book, including the massive base64 image string. Used primarily by the admin panel when editing.
* **`GET /image?id=<book_id>`**: Extracts a book's base64 string, decodes it into a binary `Uint8Array`, and serves it back with proper image MIME types and caching headers (pseudo-CDN).
* **`GET /stats`**: Returns statistics (`booksListed`, `sellersCount`, `soldCount`, `activeCount`, `pendingCount`, `visitorsCount`). It backfills any discrepancy between global totals and daily aggregate sums into a fixed launch date entry ('2026-02-20') within `system:daily_stats` for accurate Chart.js visualizations. Asynchronously fetches visitor counts from the external counter API.
* **`POST /`**: Public endpoint for user book uploads. New books default to `status: 'pending'` in KV and require admin approval. Generates a unique ID (`book:<timestamp>-<random>`). Creates or retrieves the seller's 4-digit code.
* **`PUT /?id=<book_id>`**: (Admin Auth) Updates an existing book. Preserves the `ref` field in the payload to maintain ambassador attribution.
* **`DELETE /?id=<book_id>`**: (Admin OR Seller Auth) Deletes a book. If sold, checks the `ref` field and tracks conversion in Cloudflare KV. Increments the `soldCount` in `system:stats`.
* **`PUT /admin/approve`**: (Admin Auth) Changes a book's status from `pending` to `active`.
* **`GET /sellers`**: (Admin Auth) Returns the `system:sellers` map containing seller contact numbers, names, 4-digit codes, and listings count.
* **`POST /seller/login`**: Authenticates a seller using a 4-digit code.
* **`DELETE /seller/account`**: (Seller Auth) Permanently deletes a seller account and all their associated data using the `X-Seller-Code`.
* **`POST /extract-text`**: Performs book cover text extraction (OCR) via the Groq API (`llama-3.2-90b-vision-preview`), extracting title, author, editors, and version. Handles rate limiting by rotating through multiple API keys stored as newline-separated values in the `GROQ_TOKENS` secret.
* **`POST /admin/register-fcm-token`**: Registers admin device FCM tokens to KV (`system:fcm_tokens`).
* **`POST /report` & `GET /admin/reports`**: Creates and retrieves user reports on listings, prefixed with `report:` in KV.

### Push Notifications (FCM):
The Worker uses the native Web Crypto API (avoiding Node.js dependencies) to generate JWTs from the `FCM_SERVICE_ACCOUNT_JSON` environment variable and send push notifications to admins via the FCM HTTP v1 API for new uploads and reports.

### External Integrations:
* **api.counterapi.dev**: An external free API used for high-frequency stats tracking (like visitor counts, ambassador views, and installs) to reduce KV write operations. Fetches must include a trailing slash (e.g., `..._installs/`) to prevent CORS-breaking 301 redirects. Returning a 400 Bad Request when records don't exist is an expected behavior.

## 4. Frontend File Breakdown

### `index.html` (Home - The Main User View)
* **Purpose:** The core marketplace where students browse textbooks.
* **Features:**
  * Tabbed switcher to toggle between "Buy Books" (Selling) and "Looking For Books" (Requested items).
  * Implements search filtering and sorting. Uses IndexedDB (`BooksDB`) for offline caching.
  * Books are displayed in a responsive CSS Grid with dynamic badges ("NEW", "LOOKING FOR"). Missing images trigger a fallback `onerror` placeholder.
  * Clicking a book opens a detailed Modal to initiate a WhatsApp chat directly with the buyer/seller pre-filled with context.
  * **First Launch Welcome Modal:** Prompts new users to enter/scan an ambassador referral code (persisted in `localStorage` as `dtech_ref`).
  * **Stats Modal:** Displays animated numerical counters (using `requestAnimationFrame` via `animateValue()`) for Listed Books, Active Sellers, Books Sold, and Site Visitors ("Since 20 Feb 2026").
  * **Report Listing:** Allows users to flag books. Identifies the target via a global `currentReportBookId` set during `openModal()`.

### `admin.html` (The Admin Dashboard)
* **Purpose:** A secure portal for site operators.
* **Features:**
  * 3-tab layout: **Stats Dashboard** (renders interactive data visualizations via Chart.js CDN powered by `system:daily_stats`), **Pending Approvals** queue, and **Inventory Management**.
  * Uses `localStorage` to persist the `X-Admin-Password`.
  * Integrates `Cropper.js` for image cropping prior to Base64 conversion.
  * Manages user reports (dismissing/viewing).

### `seller-manage.html` (The Seller Portal)
* **Purpose:** Standard users manage their listings via a 4-digit token (`X-Seller-Code`).
* **Features:**
  * Returning sellers initialize via `loadBooks(sellerCode)` (from sessionStorage).
  * Can upload new books directly (automatically injects cached contact info).
  * Includes a "User Manual" button explaining the code mechanism.

### `sell.html` & `request.html` (Listing Forms)
* **Purpose:** Public forms to upload a textbook to sell or request a textbook. Replaces the legacy `services.html` page.
* **Features:**
  * Strict POPIA and WhatsApp visibility checkboxes.
  * Uses the backend Groq OCR (`/extract-text`) to automatically populate title/author from the uploaded cover image (with Tesseract.js available as a client-side library in the codebase).
  * 'Looking For' books (`type: 'looking_for'`) don't strictly require images (using fallback).

### `ambassadors.html` (Ambassador Dashboard)
* **Purpose:** Dashboard for ambassadors to view their stats (referrals, views, conversions).
* **Features:**
  * Authenticates using a base64-encoded token `amb:CODE:TIMESTAMP`.
  * Handles shortcodes by stripping the `amb:` prefix with a case-insensitive regex (`/^AMB:/i`).

### `terms-modal.js`
* **Purpose:** A mandatory Legal Framework and POPIA Privacy Policy modal enforced across the frontend. Tracks acceptance in `localStorage`.

### `about.html`
* **Purpose:** The ecosystem highlight page explaining the platform and the founder, Jonas Mochebane.

## 5. Android Native Ecosystem (`app`, `admin-app`, `ambassador-app`)
The repository includes native Android modules built with Gradle:
* **`app`**: A native Android WebView wrapper for the main marketplace. Configured to support file uploads via `WebChromeClient.onShowFileChooser`.
* **`admin-app` (com.dtech.books.admin)**: Loads the admin dashboard. Exposes the device's FCM token to the web frontend using a `WebAppInterface` to enable push notifications for new books/reports.
* **`ambassador-app` (com.dtech.ambassador)**: Utilizes the ZXing library (`com.google.zxing:core`) to generate visual QR codes pointing to the public download URL of the app.

## 6. CI/CD & Deployments (GitHub Actions)
The platform uses automated GitHub workflows in `.github/workflows`:
* **`deploy-worker.yml`**: Triggers on push to the `main` branch. Deploys `worker.js` to Cloudflare using `cloudflare/wrangler-action@v4` (`wranglerVersion: '4'`). It explicitly re-uploads the `FCM_SERVICE_ACCOUNT_JSON` secret to prevent overwriting, while relying on Cloudflare to persist `GROQ_TOKENS`.
* **`build-apk.yml`**: Builds the Android debug APKs (`app`, `admin-app`, `ambassador-app`) using Java 17 and the Android SDK. It copies the main `app` APK to `marketplace.apk` at the repository root and automatically commits it back to the repo (requiring `permissions: contents: write`) so it can be served publicly via Cloudflare Pages.

## 7. Storage Keys & Data Structures Reference
* `book:<id>`: Core book listings.
* `system:sellers`: Maps seller codes to contact details and listing counts.
* `system:stats`: Global counter stats (e.g., total sold).
* `system:daily_stats`: JSON map of `YYYY-MM-DD` to daily aggregates (`soldCount`, `sellersCount`, `visitorsCount`).
* `system:fcm_tokens`: Registered push notification tokens for admin devices.
* `report:<id>`: Flagged book reports.
* `amb_stats:amb:<shortcode>`: Ambassador referral stats tracked natively in KV.
